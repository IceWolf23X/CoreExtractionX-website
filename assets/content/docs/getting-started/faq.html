Platform and dependencies

Does CoreExtractionX require a database or economy?

No. It uses three YAML files and has no database, Vault, PlaceholderAPI or economy dependency.

Does it require WorldGuard or GriefPrevention?

No hard dependency. It ignores a break only when the event was already cancelled before its HIGHEST handler.

Does it run on Spigot?

The supported target is Paper 1.21.11+. The project compiles against Paper API and is not documented for Spigot.

Rules and drops

Can any block be a source?

Any valid Bukkit/Paper material that is a block can be a source key. An enabled rule must pass the mode and replacement validation.

Does Fortune work?

REPLACEMENT calculates natural drops through Paper using the current tool and player. DROP leaves original drops to vanilla. RANDOM extra amounts can optionally multiply by Fortune.

What is the difference between MATCH_DROPS and MATCH_QUANTITY?

MATCH_DROPS uses initial generated quantity captured at LOWEST. MATCH_QUANTITY uses current event quantity at CoreExtractionX's HIGHEST handler.

What happens with the wrong tool?

There is no extra tool gate. In REPLACEMENT, Paper can calculate no natural drop while the block is still replaced and the held tool is damaged once.

What happens with Silk Touch or missing permission?

Each policy resolves per-rule then global configuration. VANILLA bypasses CoreExtractionX; DENY cancels and sends the configured message.

Operations

Can configuration be reloaded?

Yes. Both reload commands read all three files. Fatal global enum errors keep extraction safe-disabled until fixed and reloaded.

How do I report a problem?

Use the public CoreExtractionX Issues tracker with plugin/Paper/Java versions, the relevant rule, world/permission setup and reproduction steps.
