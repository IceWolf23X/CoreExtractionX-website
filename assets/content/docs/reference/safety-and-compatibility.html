Event ordering

The break listener runs at HIGHEST with ignoreCancelled=true. CoreExtractionX does nothing when another plugin has already cancelled the event. A plugin that cancels or mutates later can still interact with the result; “protection friendly” is an ordering contract, not a universal compatibility guarantee.

DROP mode captures initial generated items at BlockDropItemEvent LOWEST and applies the extra item at HIGHEST, both ignoring cancelled events.

Pending DROP correlation

The key combines world, block coordinates and player UUID. Context is removed during the matching drop event or on the next scheduler tick. This bounds stale state but means no matching event produces no extra drop.

REPLACEMENT safety

  • Same-source and AIR replacements are rejected.
  • Natural drops are calculated before the source is replaced.
  • The main-hand tool is damaged once after replacement.
  • Captured XP is spawned only when enabled.
  • No valid-tool gate exists; staging tests must include wrong tools.

DROP safety

  • Replacement must be an item.
  • Nonpositive calculated amounts spawn nothing.
  • Large amounts split by material maximum stack size.
  • Original break, durability, original drops and XP remain vanilla.

World and game-mode scope

Only SURVIVAL players in allowed worlds are considered. Creative, Adventure and Spectator remain vanilla. World matching is case-insensitive.

Compatibility boundary

CoreExtractionX has no hard protection-plugin hook. Validate every protection, custom-drop, enchantment or block-management plugin that touches the same events on a staging server.
