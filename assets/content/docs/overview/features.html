Core design

CoreExtractionX evaluates only enabled, valid rules for survival players in allowed worlds. Unconfigured blocks, non-survival players and denied worlds retain vanilla behavior.

Dynamic rules

Every child of blocks in ores.yml is a material-name rule. Source names are read case-insensitively. Invalid enabled rules are skipped with specific warnings while valid rules continue loading.

Permission fallback

A nonblank rule permission overrides the global permission. Without an override, settings.permission applies. A blank resolved permission means unrestricted. Missing permission can leave the break vanilla or deny it.

Silk Touch fallback

A rule override wins over the global setting. VANILLA makes CoreExtractionX do nothing; DENY cancels and sends the configured message.

Drop positioning and amounts

Manual drops can use block center or the face a player is actually ray-tracing. Face mode falls back to center if the trace does not identify that source block and face. Extra item amounts support fixed, random, initial-generated and current-event quantities.

Safety scope

Break and drop listeners use ignoreCancelled=true. CoreExtractionX stays out only when another plugin has cancelled before the relevant handler. It does not promise compatibility with plugins that mutate or cancel the same event later.
